# 聊天列表接真实后端

## 功能概述

把消息列表从 Mock 数据切换为真实 HTTP 请求——带 Authorization 鉴权头请求 `GET /api/messages/list`，解析响应，渲染列表。同时处理网络失败场景（显示空状态，支持下拉刷新重试）。

---

## MVVM 分层

```
View                     ViewModel              Service / 工具
──────────────────────────────────────────────────────────────────
MessagePage.ets ───────→ MessageViewModel
  @State chatList            │ getChatList()
  isLoading                  │   ├── TokenManager.getToken()
  isRefreshing               │   └── MessageService.fetchChatList(token)
  Refresh + List             │         └── GET /api/messages/list
  Empty 空状态               │              Authorization: Bearer xxx
                             │   catch → 空列表 + 日志
```

三层改动：
- **Service**：mock → 真 HTTP（改动最大）
- **ViewModel**：加 token 传递 + try-catch（改动中等）
- **View**：加空状态 UI（改动最小）

因为 MVVM 分层清晰，Service 从 mock 换成真请求，ViewModel 和 View 几乎不需要感知——这就是 MVVM 的价值。

## 通过这个功能你能学到的鸿蒙知识

### 1. GET 请求与 Authorization 头 — token 终于用起来了

```typescript
const response = await httpRequest.request(
  `${BASE_URL}/api/messages/list`,
  {
    method: http.RequestMethod.GET,   // 和 POST 不同，GET 不需要 extraData
    header: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`  // 标准鉴权头格式
    },
    connectTimeout: 10000,
    readTimeout: 10000
  }
);
```

**关键点：**
- GET 请求没有 `extraData`（没有请求体）
- Authorization 头格式：`Bearer <token>`，空格不能少
- 登录/注册时存的 token 在这里被真正使用
- 后续所有需要鉴权的接口都这样带 token

**POST vs GET 对比：**

| | POST（登录/注册） | GET（获取消息列表） |
|---|---|---|
| method | `http.RequestMethod.POST` | `http.RequestMethod.GET` |
| extraData | `JSON.stringify(body)` | 无 |
| Authorization | 用户还没登录，不需要 | `Bearer <token>` 必须带 |

### 2. JSON 数据转类实例 — @Observed 的要求

```typescript
// ❌ 直接返回 JSON.parse 的数据
return result.data;  // 这些是普通对象，不是 MessageItem 实例

// ✅ 映射成 MessageItem 实例
return result.data.map((item: MessageItem) =>
  new MessageItem(item.id, item.name, item.lastMessage, item.time, item.unreadCount)
);
```

**关键点：**
- `@Observed` 装饰的类创建的是「可观测对象」，`@ObjectLink` 能追踪它的属性变化
- JSON.parse 生成的是普通对象，不是类的实例，`@ObjectLink` 追踪不到
- 从任何 API 返回的数组数据，都需要手动 `map` 成类实例

### 3. try-catch 保底 — 网络请求会失败

```typescript
async getChatList(): Promise<MessageItem[]> {
  try {
    const token = await TokenManager.getToken();
    this.chatListData = await MessageService.fetchChatListFromServer(token);
  } catch (e) {
    // 网络失败、服务器错误、解析错误……都会进这里
    console.error('获取消息列表失败：' + (e as Error).message);
    this.chatListData = [];  // 兜底：返回空列表，UI 不至于崩溃
  }
  return this.chatListData;
}
```

**关键点：**
- 之前的 Mock 数据永远不会失败，但真网络会
- ViewModel 是最适合加 try-catch 的地方——它管业务逻辑
- 失败时的策略：返回空列表 + 记日志，让 UI 显示「暂无消息」而不是白屏

---

### 4. 空状态 UI — 不要给用户看空白页

```typescript
if (this.chatList.length === 0) {
  // 空状态：明确告诉用户「没有数据」，并给出操作建议
  Column() {
    Text('暂无消息')
    Text('下拉刷新重试')
  }
}
```

**关键点：**
- 空白页面让用户困惑（是加载中？卡住了？没数据？）
- 空状态文字 + 操作提示解决这个问题
- 把 `Refresh` 组件提出来包裹空状态，让用户在任何状态下都能下拉重试

## 数据流全链路

```
MessagePage.aboutToAppear()
  → loadData()
    → MessageViewModel.getChatList()
        ├── TokenManager.getToken()           ← 读本地 token
        ├── MessageService.fetchChatList(token)
        │     ├── http.createHttp()
        │     ├── GET /api/messages/list
        │     │   Header: Authorization: Bearer xxx
        │     ├── JSON.parse(response.result)
        │     ├── code === 0 → map → MessageItem 实例
        │     └── httpRequest.destroy()
        └── 存到 chatListData

    ← MessageItem[]
  → @State chatList = [...data]
  → UI 渲染列表（或空状态）
```

---

## Mock → 真实请求，只改了 3 个文件

这是 MVVM 的价值：Service 从 `setTimeout` 模拟变成 `@ohos.net.http` 真实请求，ViewModel 和 View 的改动非常小：

- ViewModel 只加了 token 传递和 try-catch
- View 只加了空状态

如果将来要换网络库（比如换 WebSocket、换 gRPC），也只需要改 Service 层。
