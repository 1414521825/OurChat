# 登录功能

## 功能概述

实现 App 的登录页面和完整登录流程：首次打开 → 显示登录页 → 输入用户名密码 → 调后端 API → 保存 token → 进入主界面。再次打开 → 检测到本地有 token → 跳过登录页直接进入主界面。

---

## 架构：如何符合 MVVM

```
┌─────────────────────────────────────────────┐
│  View (UI 层)                               │
│  LoginPage.ets  ───  纯 UI，只管画界面       │
│  Index.ets       ───  根页面，管页面切换     │
├─────────────────────────────────────────────┤
│  ViewModel (业务逻辑层)                      │
│  AuthViewModel.ets ─── 校验 / 编排 / 存结果  │
├─────────────────────────────────────────────┤
│  Service (数据层)                           │
│  AuthService.ets   ─── 发 HTTP 请求         │
│  TokenManager.ets  ─── 本地持久化读写       │
├─────────────────────────────────────────────┤
│  Model (数据类型)                            │
│  LoginModel.ets    ─── 请求体 / 响应体类型   │
└─────────────────────────────────────────────┘
```

每层只干自己的事，数据单向流动：

```
用户点击 → View 调 ViewModel
              → ViewModel 调 Service
                   → Service 发 HTTP / 读写存储
                   ← 返回数据
              ← ViewModel 处理结果
         ← View 根据结果更新 UI
```

### 各文件职责

| 文件 | 层 | 职责 |
|---|---|---|
| `models/LoginModel.ets` | Model | 定义 `LoginRequest`（发给后端）、`LoginData`（后端返回）、`LoginResult`（ViewModel 返回给页面）的数据结构 |
| `services/AuthService.ets` | Service | 封装 `@ohos.net.http`，发 POST 请求到 `/api/auth/login`，解析响应 |
| `utils/TokenManager.ets` | Service/工具 | 封装 `@kit.ArkData` 的 Preferences API，实现 token 的存、取、清、判 |
| `viewmodels/AuthViewModel.ets` | ViewModel | 输入校验 → 调 Service → 存 token → 返回统一结果对象 |
| `pages/LoginPage.ets` | View | 登录表单 UI：用户名输入框、密码输入框、登录按钮、加载态 |
| `pages/Index.ets` | View/容器 | 启动时判登录态，三态切换：加载中 / 登录页 / 主界面 |
| `entryability/EntryAbility.ets` | 入口 | 启动时初始化 `TokenManager` |

## 通过这个功能你能学到的鸿蒙知识

### 1. Preferences API — 本地持久化存储

```typescript
import { preferences } from '@kit.ArkData';

// 获取存储实例（需要 context）
const store = await preferences.getPreferences(context, 'store_name');

// 写
await store.put('key', 'value');
await store.flush(); // 必须 flush 才会真正写入磁盘

// 读
const value = await store.get('key', '默认值');

// 删
await store.delete('key');
await store.flush();
```

**关键点：**
- `getPreferences` 是异步的，必须 `await`
- 写/删操作后必须调 `flush()`，否则数据不会持久化
- 需要 `Context`，在 `EntryAbility` 里拿 `this.context`

**在项目中：** `TokenManager.ets` 封装了这套 API，业务代码不需要直接碰 `preferences`。

### 2. @ohos.net.http — 发 HTTP 请求

```typescript
import { http } from '@kit.NetworkKit';

const httpRequest = http.createHttp();

const response = await httpRequest.request(url, {
  method: http.RequestMethod.POST,
  header: { 'Content-Type': 'application/json' },
  extraData: JSON.stringify({ key: 'value' }),  // 请求体
  connectTimeout: 10000,  // 连接超时 ms
  readTimeout: 10000      // 读取超时 ms
});

// response.result 是后端返回的 body（JSON 字符串时是 string 类型）
const data = JSON.parse(response.result as string);

// 用完后必须销毁，释放网络资源
httpRequest.destroy();
```

**关键点：**
- `http.createHttp()` 创建一个客户端实例
- `extraData` 是请求体，需要手动 `JSON.stringify`
- `response.result` 类型取决于后端返回的 Content-Type
- **必须调 `destroy()`**，否则内存泄漏。通常放在 `try...finally` 里

**在项目中：** `AuthService.ets` 是第一个真正用这个 API 的 Service。

### 3. ArkTS 严格模式 — 不允许匿名对象字面量

ArkTS 比 TypeScript 更严格，不允许这种写法：

```typescript
// ❌ 错误：匿名对象字面量
return { success: false, message: '请输入用户名' };

// ❌ 错误：匿名类型标注
async login(): Promise<{ success: boolean; message: string }> { ... }
```

必须显式声明类：

```typescript
// ✅ 正确：显式声明类
export class LoginResult {
  success: boolean;
  message: string;

  constructor(success: boolean, message: string) {
    this.success = success;
    this.message = message;
  }
}

// ✅ 使用
return new LoginResult(false, '请输入用户名');
```

**这个限制贯穿整个 ArkTS 开发**，遇到 `arkts-no-untyped-obj-literals` 报错就说明你需要声明一个类。

### 4. @State 与组件状态驱动

```typescript
@State username: string = '';  // 状态变量

// build() 里绑定
TextInput({ text: this.username })  // 状态 → 组件
  .onChange((value) => { this.username = value; })  // 组件 → 状态
```

**关键点：**
- `@State` 标记的变量变化时，`build()` 会自动重新执行，UI 自动更新
- `TextInput` 用构造参数 `{ text: xxx }` 传值，**没有** `.value()` 方法
- `onChange` 回调把用户输入同步回 `@State`

---

### 5. 组件生命周期 — aboutToAppear

```typescript
async aboutToAppear() {
  // 在 build() 之前执行，适合做初始化（加载数据、检查登录态等）
  this.isLoggedIn = await TokenManager.isLoggedIn();
  this.isChecking = false;
}
```

**关键点：**
- `aboutToAppear()` 在首次 `build()` **之前**被调用
- 支持 `async`，可以 `await` 异步操作
- 适合做数据预加载

### 6. UIAbility 生命周期与异步

```typescript
export default class EntryAbility extends UIAbility {
  onCreate(want, launchParam): void { ... }          // 同步，App 创建时
  async onWindowStageCreate(windowStage): Promise<void> { ... }  // 支持 async，窗口创建时
  onForeground(): void { ... }                       // App 切到前台
  onBackground(): void { ... }                       // App 切到后台
  onDestroy(): void { ... }                          // App 销毁
}
```

**关键点：**
- `onCreate` 里可以拿到 `this.context`
- `onWindowStageCreate` 支持 `async`——适合做需要等异步完成的初始化
- `windowStage.loadContent('pages/Index', callback)` 加载入口页面

### 7. 单例模式（项目惯例）

```typescript
class AuthService { ... }
export default new AuthService();  // 导出一个实例，不是类
```

```typescript
import AuthService from '../services/AuthService';  // 拿到的就是那个唯一实例
```

**关键点：**
- `export default new Xxx()` 确保全局只有一个实例
- 导入时不需要 `new`，直接用
- 适合 Service 和 ViewModel 这种全局只需一份的对象

### 8. 条件渲染

```typescript
build() {
  if (this.isChecking) {
    // 状态 A：加载中
    LoadingProgress()
  } else if (!this.isLoggedIn) {
    // 状态 B：未登录
    LoginPage({ onLoginSuccess: () => { this.isLoggedIn = true; } })
  } else {
    // 状态 C：已登录
    Navigation(this.pageStack) { /* Tabs 主界面 */ }
  }
}
```

**关键点：**
- ArkUI 的 `build()` 里可以直接用 `if/else` 做条件渲染
- 状态变化时，自动切换到对应分支
- 回调函数可以修改父组件的 `@State`，触发重新渲染

## 数据流全链路（跟着走一遍）

```
1. App 冷启动
   EntryAbility.onCreate()
     └── NetworkManager.init()           ← 网络监听

2. 窗口创建
   EntryAbility.onWindowStageCreate() [async]
     └── await TokenManager.init(ctx)    ← 初始化本地存储（等它完成）
     └── loadContent('pages/Index')      ← 加载页面

3. Index 渲染
   aboutToAppear()
     └── TokenManager.isLoggedIn()       ← 读本地 token
     └── isChecking = false, isLoggedIn = (有 token ? true : false)

   build()
     ├── 有 token → Navigation + Tabs   ← 直接进主界面
     └── 无 token → LoginPage           ← 显示登录页

4. 用户输入账号密码，点击登录
   LoginPage.handleLogin()
     └── AuthViewModel.login(user, pwd)
           ├── 非空校验
           ├── AuthService.login(req)    ← @ohos.net.http POST
           │     └── 后端返回 { code:0, data:{ token, userId, username } }
           └── TokenManager.saveToken()  ← 写本地

5. 登录成功
   Index.isLoggedIn = true               ← 回调触发
   build() 切到 Navigation + Tabs       ← 进入主界面

6. 下次冷启动
   Index.aboutToAppear()
     └── TokenManager.isLoggedIn() → true  ← 本地有 token
   build() → Navigation + Tabs            ← 直接进主界面，跳过登录
```

## 后端 API 约定

> 这部分等你确认后端格式后修改

- **URL**: `POST /api/auth/login`
- **请求体**: `{ "username": "xxx", "password": "xxx" }`
- **响应体**: `{ "code": 0, "message": "ok", "data": { "token": "...", "userId": "...", "username": "..." } }`
- `code === 0` 表示成功，非 0 表示业务错误

需要修改时，改 `models/LoginModel.ets` 的字段名，和 `services/AuthService.ets` 的 URL 即可。
