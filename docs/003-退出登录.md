# 退出登录

## 功能概述

在「我的」页面点击退出登录 → 清除本地 token 和缓存 → 异步通知后端 → 切换到登录页。核心设计原则：**用户体验优先于服务端一致性**——先让用户退出去，后端通知失败不影响本地退出。

---

## MVVM 分层

```
View                     ViewModel             Service / 工具          Model
─────────────────────────────────────────────────────────────────────────────
ProfilePage.ets ───────→ AuthViewModel.logout()
                              │
                              ├── TokenManager.clear()       ← 复用
                              ├── MessageViewModel.clear()   ← 复用
                              ├── AuthService.logout()           LogoutRequest
                              │     └── POST /api/auth/logout   (userId)
                              │         fire-and-forget
                              └── return LoginResult              LoginResult
                                     ↓
                         onLogoutSuccess() 回调 → Index
                             isLoggedIn = false → 切回 LoginPage
```

和登录/注册不同，退出登录的 Service 调用采用 **fire-and-forget** 模式——不 await 结果，不阻塞 UI。

## 通过这个功能你能学到的鸿蒙知识

### 1. Fire-and-Forget 模式 — 不 await 的异步调用

```typescript
// 普通异步：等后端返回才继续
const data = await AuthService.login(request);

// Fire-and-forget：发出请求就不管了，继续执行
AuthService.logout(request).catch((e: Error) => {
  console.error('后端退登通知失败：' + e.message);
});
```

**关键点：**
- 不 `await` 意味着不阻塞当前函数，后面代码立即执行
- 但 Promise 可能 reject，需要用 `.catch()` 捕获错误，否则会有未处理的异常
- 适用场景：用户不需要等待结果的操作（退出通知、埋点上报、日志记录）

**在这个功能里：** 用户点了退出，应该立即看到反馈（切到登录页），不能因为后端响应慢就卡住。

---

### 2. 退出时清理缓存 — 防止数据泄露

```typescript
async logout(): Promise<LoginResult> {
  await TokenManager.clear();      // 清持久化存储（token、userId）
  MessageViewModel.clear();        // 清内存缓存（聊天列表）
  // ... 后续异步通知后端
}
```

**关键点：**
- 退出登录不只是删 token——所有和当前用户相关的缓存都要清
- 不清的后果：A 用户退出 → B 用户登录 → B 看到 A 的聊天列表
- 需要清理的两类数据：
  - **持久化存储**（TokenManager）：token、userId
  - **内存缓存**（ViewModel）：聊天列表、联系人缓存等

---

### 3. 回调穿透深层组件 — 子传父的标准模式

```typescript
// Index.ets（父）→ 传回调给 ProfilePage
TabContent() {
  ProfilePage({
    onLogoutSuccess: () => {
      this.isLoggedIn = false;  // 父组件改状态，触发重新渲染
    }
  })
}

// ProfilePage.ets（子）→ 声明回调 prop
onLogoutSuccess?: () => void;

// 合适时机触发
.onClick(async () => {
  await AuthViewModel.logout();
  this.onLogoutSuccess?.();  // 通知父组件
})
```

**关键点：**
- 子组件不直接改父组件状态，只「通知」父组件
- 父组件在回调里改 `@State`，驱动 UI 切换
- 和 LoginPage → Index 的模式完全一样，一个套路反复用

---

### 4. Service 方法简化 — 不需要返回值时就返回 void

```typescript
// AuthService.ets
async logout(request: LogoutRequest): Promise<void> {
  const httpRequest = http.createHttp();
  try {
    await httpRequest.request(...);
    // 不需要解析 response，返回 void 即可
  } finally {
    httpRequest.destroy();
  }
}
```

**关键点：**
- 方法签名准确反映需求——不需要返回值就写 `Promise<void>`
- 不是每个 HTTP 请求都要解析 JSON 响应
- `try...finally` 确保 httpRequest 一定会被销毁

---

### 5. 用户操作优先于服务端一致性

```
用户体验优先：
  点退出 → 立即清理本地 → 立即切页面 → 用户感知：秒退

服务端一致性次之：
  后台异步发请求通知后端 → 失败了也没关系 → 下次登录重新认证
```

**关键点：**
- 客户端不能依赖服务端 100% 可用
- 涉及用户体验的操作（退出、保存草稿），优先保证本地响应速度
- 后端同步操作用 fire-and-forget，失败不影响本地状态

## 数据流全链路

```
用户在「我的」页 → 点击「退出登录」
  → ProfilePage.handleLogout()
    → AuthViewModel.logout()
        ├── ① await TokenManager.clear()       ← 删持久化 token
        ├── ① MessageViewModel.clear()         ← 清内存聊天缓存
        ├── ② AuthService.logout(req)          ← POST /api/auth/logout
        │       .catch(e => console.error)      ← fire-and-forget，失败只记日志
        └── return LoginResult(true, '已退出登录')
  → promptAction.showToast('已退出登录')
  → onLogoutSuccess()                           ← 回调
    → Index.isLoggedIn = false                  ← 状态切换
    → build() 销毁主界面，创建 LoginPage        ← UI 切换

下次冷启动：
  Index.aboutToAppear()
    → TokenManager.isLoggedIn() → false         ← 本地已无 token
    → 显示 LoginPage                             ← 需要重新登录
```
